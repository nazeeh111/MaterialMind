# MATERIALMIND foundations and protocol

Research inspected 2026-10-25. This is a design recommendation based on primary source inspection, not a report of completed local experiments.

## Tractable real-data route

Use a deterministic, label-blind subset of WBM initial structures. The public Matbench Discovery Figshare article is [22715158](https://api.figshare.com/v2/articles/22715158), currently public and licensed **CC BY 4.0**. It identifies WBM as test data and MP as training data. Attribute Janosh Riebesell and the original WBM authors, link the source, identify changes/subsetting, and preserve a separate data license from the project's code license. Approximately 64 MB compressed suffices for the following three inputs:

### Target and normalization

The label is the signed distance `e_above_hull_mp2020_corrected_ppd_mp` in **eV/atom**, computed against a fixed Materials Project DFT hull. Negative values can describe candidates below the existing reference hull. Stable means distance <= 0 (with an explicitly documented numerical tolerance); do not silently replace the task with a 0.1 eV/atom metastability threshold or clip all negative values to zero. Formation energy alone is not stability.

Join model CSVs by `material_id`; the prediction column is `e_form_per_atom`. The upstream [loader implementation](https://raw.githubusercontent.com/janosh/matbench-discovery/main/matbench_discovery/data.py) derives:

`predicted_signed_hull_distance = predicted_formation_energy + reference_hull_distance - reference_formation_energy`

where the summary reference formation field is `e_form_per_atom_mp2020_corrected`. The subtraction is a composition-dependent fixed reference-hull offset, not candidate information to train on. Store and describe it as a reference state. Do not expose either candidate label separately to the acquisition model. Never use the upstream absolute prediction-error filtering against DFT, because that consults hidden candidate outcomes. Likewise, upstream `unique_prototype` may select the most stable reference result per prototype; do not use it for a supposedly outcome-blind sample selection.

CHGNet 0.3.0 targets already include MP2020 corrections. Applying the compatibility corrections again would corrupt normalization. Raw CHGNet total energy predictions are not equivalent to hull distance. New imported compositions need compatible reference states before stability can be claimed.

## Model and software choices

- **CHGNet 0.3.0:** compact 412,525-parameter pretrained crystal graph model with a small checkpoint and published relaxed-structure energy predictions. It was trained on MPtrj (MP release v2021.11.10 data, fetched in September 2022), not on the present project's adaptation split. Cached benchmark predictions give a reproducible low-compute starting point; local frozen crystal embeddings or predictions can be computed separately. Code and checkpoint are BSD-3-Clause per the model sidecar. Its source is [CederGroupHub/chgnet](https://github.com/CederGroupHub/chgnet). This is a baseline foundation, not a claim to be the best available 2026 model.
- **MatGL:** [current README](https://raw.githubusercontent.com/materialyzeai/matgl/main/README.md) reports the May 2026 v3 change to PyTorch Geometric and corrected message aggregation with reissued weights; old examples and old weights are not interchangeable. Its [license](https://raw.githubusercontent.com/materialyzeai/matgl/main/LICENSE) is BSD-3-Clause. Avoid adding its runtime merely to list it as an integration.
- **pymatgen:** use its periodic geometry, symmetry and CIF tools. The [current README](https://raw.githubusercontent.com/materialsproject/pymatgen/master/README.md) says basic structures/I/O moved into `pymatgen-core`, while `pymatgen` reexports them and adds higher-level analysis. The [license](https://raw.githubusercontent.com/materialsproject/pymatgen/master/LICENSE) is MIT. Validate actual installed versions and use explicit symmetry tolerances.
- **BoTorch:** [official source](https://raw.githubusercontent.com/meta-pytorch/botorch/main/README.md) is MIT and provides modular Gaussian-process Bayesian optimization. A CPU finite-pool expected-improvement baseline can use a GP and the standard analytic EI formula without making BoTorch mandatory; describe the actual implementation, not a fictional dependency. A BoTorch optional reference implementation earns inclusion only if tested.
- **Matbench:** [official project](https://raw.githubusercontent.com/materialsproject/matbench/main/README.md) provides 13 materials-property tasks, a different setting from WBM discovery. Its [code license](https://raw.githubusercontent.com/materialsproject/matbench/main/LICENSE) is MIT; constituent datasets still have separate provenance. Do not relabel this WBM experiment a Matbench leaderboard submission.
- **Newer alternatives:** [eSEN](https://arxiv.org/abs/2502.12147) is relevant because it tests downstream physical fidelity and energy conservation, and cautions that held-out point errors do not alone establish useful physical behavior. [FAIRChem](https://github.com/facebookresearch/fairchem) now includes UMA and faster 2026 inference paths, with hardware and model-specific licensing/provenance. Those models merit a later controlled backbone comparison, rather than an untested claim that CHGNet is superior. Training-data overlap must be audited separately for each checkpoint.

## Scientific background that changes the design

The supplied [2025 Nature Machine Intelligence study](https://doi.org/10.1038/s42256-025-01055-1), with [accessible author preprint](https://arxiv.org/abs/2308.14920), distinguishes formation energy from thermodynamic stability and retrospective from prospective discovery. The live benchmark covers multiple tasks and model families, so old leaderboard ranks should not be presented as current universal rankings.

[Ho, Ortner and Wang, 2026](https://doi.org/10.1038/s41524-026-02080-3) study flexible uncertainty calibration for ML interatomic potentials, including environment-dependent uncertainty and the effect on high-error selection. Their results motivate testing calibration, not assuming a probability or interval is useful for finding stable phases. [Perez et al., 2025](https://www.nature.com/articles/s41524-025-01758-4) show why model misspecification matters: uncertainty based only on fitted-parameter variation can miss systematic error. [NIST's reference-data benchmark](https://www.nist.gov/publications/benchmarking-active-learning-strategies-materials-optimization-and-discovery) supports comparing acquisition functions on controlled real-data campaigns. These are related prior art, so a cost/uncertainty/diversity combination should be described as this project's method and empirical investigation, not as an unprecedented invention.

## Recommended frozen evaluation protocol

1. Record selection rule before inspecting outcomes: for example choose chemically valid, ordered initial structures with 2–4 elements and <= 32 sites; sort by SHA256(material_id + a fixed seed); take a fixed N. Bound and justify the chemistry using input features. Do not condition inclusion on true stability, formation-energy error or a reference-selected representative.
2. Reject malformed/nonfinite cells, partial occupancy if unsupported, overlapping periodic sites and duplicate initial structures. Use `StructureMatcher` with fixed tolerances after an inexpensive composition bucket. Alloys should not be rejected just because oxidation states cannot be assigned. Symmetry is a measured tolerance-dependent metadata field, not proof of uniqueness.
3. Split by reduced composition to keep polymorphs together. For a stronger prototype-transfer experiment, group initial anonymous prototypes too, assigning connected groups together, then report achieved sizes and distribution shift. If that grouping collapses the sample into too few groups, report the limit and narrow the claim rather than quietly falling back to random rows. Retain an overlap audit.
4. Separate development/training, uncertainty calibration, policy-validation and untouched final evaluation pools. Fit scalers, projections, regression/classification heads and probability calibration only on allowed earlier pools. Freeze acquisition hyperparameters and budget before final evaluation. This adapts on a subset of the official WBM test data and is therefore **not an official blind Matbench Discovery result**.
5. The acquisition model sees initial structure descriptors, frozen model outputs/embeddings and allowed reference-hull states. Candidate outcomes live behind an oracle interface that logs each reveal. Refit during a campaign using only its initial training data plus already queried outcomes; never all pool outcomes. Offline metric computation may read all final labels after the run, without feeding them into recommendations.
6. Compare random, lowest predicted hull distance, greatest predictive uncertainty, farthest-point diversity and Gaussian-process expected improvement. Use paired pool/initialization seeds and identical candidate pools, initial labels, batch sizes and evaluation-count budgets. Cost-sensitive methods additionally need plots under the same cumulative cost budget. If cost is a formula such as normalized site-count cubed, call it a **proxy**, not measured DFT runtime.
7. Train/adapt the method on development data: a stability learner plus calibrated probabilities, structural novelty and cost, with policy weights selected from development episodes under a declared stable-yield-per-cost objective. State exactly what was learned versus fixed. Keep a property-greedy baseline with the same learned prediction head to distinguish policy effects from a better surrogate.
8. Ablate calibration, cost, diversity and online update individually. For the calibration test, keep the same predictive head and policy weights where possible; otherwise distinguish the effects of changed ranking and tuned hyperparameters. Compare probability calibration (Brier score/reliability bins), interval coverage/sharpness and actual stable discoveries. A global conformal multiplier can change interval width without changing uncertainty order, so it need not improve acquisition.
9. At multiple budgets report stable count, precision@K, recall of pool-stable candidates, discovery enrichment over random, simple regret and the exact regret definition, diversity (unique chemical systems plus descriptor spread), total wall time, feature/inference time and acquisition fit time. Report multiple seeds and paired bootstrap confidence intervals. Seed intervals describe stochastic campaign variability on this one finite pool; they do not prove transfer to all chemistry. Preserve per-step, per-candidate records and all failures.
10. A held-out replay using previously computed DFT labels is a **retrospective discovery evaluation**. CHGNet relaxations, cached predictions, electronic DFT calculations and synthesis are distinct evidence types. No prospective discovery or synthesis claim follows from these experiments. Negative results and failure modes belong in the main findings.

## PaperVizAgent investigation

The official [Google Research PaperVizAgent README](https://raw.githubusercontent.com/google-research/papervizagent/main/README.md) describes planner/stylist/visualizer/critic stages and requires model/API configuration for image generation. The [configuration template](https://raw.githubusercontent.com/google-research/papervizagent/main/configs/model_config.template.yaml) supplies Google/Vertex, OpenAI and Anthropic credential fields; a free subscription-backed local execution path is not documented. Under the no-billed-API constraint, do not acquire credentials or imply it was run. Retain an editable SVG/Mermaid architecture and scientific-method diagram instead, with quantitative figures rendered directly from actual experiment outputs. This meets the investigation requirement while preserving cost and scientific accuracy.

## Field audit from WBM documentation

The [WBM README](https://raw.githubusercontent.com/janosh/matbench-discovery/main/data/wbm/readme.md) identifies the initial JSONL fields as `material_id`, `formula_from_cse`, and `initial_structure`. Summary `volume` and `protostructure_spglib` describe the **DFT-relaxed** geometry; `bandgap_pbe` and `site_stats_fingerprint_init_final_norm_diff` also require the completed reference evaluation. None belongs in a label-blind recommendation feature vector. Compute volume, distances, coordination and symmetry from `initial_structure`; `protostructure_spglib_initial_structure` is an allowed grouping signal. The initial prototype string can retain element identities, so inspect its syntax before calling it an anonymous prototype. The upstream original study performed five substitution generations; the first integer in `wbm-<step>-<index>` identifies that generation. Avoid accidental first-file-row sampling that only covers generation 1.
